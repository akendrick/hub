Section 01

Architecture

kaslo-api.php is fully self-contained. It fetches all data sources directly and caches results to /tmp/kaslo_*.json. It must never make HTTP calls back to knotwork.ca — self-referencing calls on this host silently hang or fail.

Section 02

PHP Backend Rules

These are the rules that were learned the hard way — each gotcha below caused a real outage or silent bug.

Critical gotchas

Gotcha 1 — Non-ASCII characters

Never put non-ASCII characters in PHP files. Box-drawing chars (─, │, └), em-dashes (—), arrows (→, ←), and any Unicode outside ASCII cause silent PHP parse errors on the server. This includes characters that look fine in a local editor.

Safe alternatives: use ->, ==>, plain hyphens ---, and HTML entities (&middot;, &rarr;) in string literals.

Gotcha 2 — Ternary on left side of assignment

Do not use a ternary expression as the left-hand side of an array push. ($a ? $b : $c)[] = $x is illegal in PHP 8 and causes a parse error.

Use a temporary variable or an if/else block instead:

// WRONG — illegal in PHP 8
($pri <= 2 ? $urgent : $rest)[] = $item;

// RIGHT — assign first, then push
$target = ($pri <= 2) ? 'urgent' : 'rest';
$$target[] = $item;

// or simply:
if ($pri <= 2) { $urgent[] = $item; } else { $rest[] = $item; }
Gotcha 3 — OPcache serves stale bytecode

After uploading any PHP file, run kaslo-flush.php immediately. OPcache on this host persists compiled bytecode across requests. Uploading a new file does not invalidate it automatically — the old code keeps running.

kaslo-flush.php calls opcache_invalidate() and opcache_reset(), then rebuilds the weather and calendar caches.

Gotcha 4 — File paths

Hand-edited todos are at data/todos.json (relative to web root). The /tmp/kaslo_*.json files are auto-managed by kaslo-api.php — never edit them by hand.

Gotcha 5 — DGS quick_status.php is broken

quick_status.php returns unknown_user for all accounts. kaslo-api.php fetches the SGF endpoint directly for board position. Do not attempt to restore quick_status — it's a DGS server issue.

Gotcha 6 — Open-Meteo moon_phase removed

The daily=moon_phase parameter to Open-Meteo now returns an error. Moon phase is computed from first principles using the Julian Date formula in compute_moon_phase(). Do not re-add moon_phase to any Open-Meteo URL.

File I/O patterns

Always use these helper patterns — they handle missing files and malformed JSON gracefully:

// Reading a cache file — returns null if missing or invalid
function read_cache(string $path): ?array {
    if (!file_exists($path)) return null;
    $d = json_decode(file_get_contents($path), true);
    return is_array($d) ? $d : null;
}

// Reading /tmp cache with TTL — returns null if expired
function cache_get(string $name, int $ttl): ?array {
    $p = '/tmp/kaslo_' . $name . '.json';
    if (!file_exists($p) || time() - filemtime($p) >= $ttl) return null;
    $d = json_decode(file_get_contents($p), true);
    return is_array($d) ? $d : null;
}

// Writing /tmp cache atomically
function cache_set(string $name, array $d): void {
    file_put_contents('/tmp/kaslo_' . $name . '.json', json_encode($d), LOCK_EX);
}

Always default-to-empty when reading a cache: read_cache(...) ?? []. Never assume the cache file exists or is current — it may be missing on a fresh deploy or after kaslo-flush.php.

Output format

All output from kaslo-api.php must be a flat JSON object — no nested objects, no arrays at the top level. TRMNL's Liquid engine accesses variables by name; nested structure becomes inaccessible.

// RIGHT — flat top-level keys
{
  "temp": "15",
  "feels": "13",
  "go_opponent": "GreenMonk",
  "cal_d0_dow": "Tue",
  "todo_u0_text": "Report Cards"
}

// WRONG — nested objects are unreachable in Liquid
{
  "wx": { "temp": "15", "feels": "13" },
  "go": { "opponent": "GreenMonk" }
}

Only bare aliases (temp, not wx_temp) are in the flat output. The nested wx, fc, todo, cal, go objects are also present; TRMNL auto-flattens one level using underscores (go.opponent → go_opponent).

Section 03

Plugin & Liquid Rules

TRMNL plugins are HTML/CSS/Liquid templates. The Liquid dialect has a few surprises that differ from standard Liquid or Jinja.

Variable access

01
Use plain {{ }} and {% %} delimiters. No ## prefix. TRMNL's Liquid is standard Ruby Liquid.
02
Single polling URL = IDX_0 namespace for all variables. When only one URL is configured, every variable is accessed as a bare name: {{ temp }}, {{ go_opponent }}, {{ cal_d0_dow }}.
03
Check existence before rendering. Use {% if go_opponent != "" %} rather than assuming a value is present — caches can be missing or stale after a flush.
04
For integers, compare without quotes: {% if go_my_turn_count > 0 %}. For strings, compare with quotes: {% if go_color == "b" %}.
05
Paste only the HTML between the fences. Do not include the markdown header block or the ` ```html ` / ` ``` ` fences themselves when pasting into the TRMNL plugin editor.

Time is available via {{ trmnl.user.time | date: "%H:%M %a %-d" }} — this uses TRMNL's built-in device time, not a variable from the API.

Layout: JS-driven sizing

The TRMNL X renders at 1040×780 CSS pixels (landscape) or 780×1040 (portrait), backed by a native 1872×1404 panel at scale_factor 1.8. Never hardcode these dimensions — always compute layout from window.innerWidth and window.innerHeight, which report the correct values natively in both orientations.

The canonical pattern (from plugin-dgs-v3.md):

var VW   = window.innerWidth  || 1040;
var VH   = window.innerHeight || 780;
var HDR  = 28;                           // header bar height
var avail = VH - HDR;

// Derive section heights as proportions of available space
var TOP_H = Math.floor(avail * 0.24);    // ~180px at 780
var FC_H  = Math.max(88, Math.floor(avail * 0.18));
var CAL_H = avail - TOP_H - FC_H;

// Stamp explicit px values onto elements — do NOT rely on CSS %
document.getElementById('top').style.height  = TOP_H + 'px';
document.getElementById('fc').style.height   = FC_H  + 'px';
document.getElementById('cal').style.height  = CAL_H + 'px';
A
Set width:100%;height:100% on html and body. Use overflow:hidden — e-ink has no scrollbars.
B
Use flex-shrink:0 on fixed-height elements (header, forecast strip) so they don't compress when the main content fills remaining space.
C
Stamp px values from JS, not CSS %, for all major section heights. CSS percentages can misbehave inside flex containers on the TRMNL rendering engine.
D
Use white-space:nowrap; overflow:hidden; text-overflow:ellipsis on all text that could overflow. Long event names and opponent handles will always push past their container.

Go board rendering

Section 04

Testing Strategy

There's no CI pipeline — tests are pragmatic local scripts and remote smoke checks. Four levels, each catching a different class of bug.

Level 1 — PHP syntax check PHP Before every upload

Run PHP's built-in linter against every PHP file before transferring it to the server. This catches non-ASCII parse errors, ternary-on-LHS issues, and any other syntax problem — instantly, with no server involved.

php -l kaslo-api.php
php -l kaslo-flush.php

A clean file prints: No syntax errors detected in kaslo-api.php. Any other output means do not upload.

Make this a habit: run php -l before every FTP/SFTP transfer. It takes under a second and catches the most painful class of errors before they reach the server.

Level 2 — Fixture-based local test PHP After logic changes

Maintain a test-fixtures/ directory with representative JSON snapshots of the cache files. Pre-populate /tmp/ with them and run kaslo-api.php via CLI to verify output keys and values without touching the live server.

Directory structure:

test-fixtures/
  kaslo_wx.json            # typical EcoWitt real-time response
  kaslo_forecast3.json     # Open-Meteo 7-day forecast + pressure
  kaslo_ical.json          # parsed 4x iCal feeds, 14-day window
  todos.json               # mix of urgent and rest items

Running the test:

# Seed /tmp caches with fixtures, then run locally
cp test-fixtures/kaslo_wx.json        /tmp/
cp test-fixtures/kaslo_forecast3.json /tmp/
cp test-fixtures/kaslo_ical.json      /tmp/
cp test-fixtures/todos.json           data/todos.json

php -r '
  $_SERVER["DOCUMENT_ROOT"] = getcwd();
  $_GET = ["key" => "kw_40e818911c1980bcd56dc4aff37a820f811990a130eb771fd9e21a536edc55ea", "game" => "0"];
  ob_start();
  include "kaslo-api.php";
  $out = json_decode(ob_get_clean(), true);

  // Assert required keys exist
  $required = ["temp","condition","go_opponent","todo_u0_text","cal_d0_dow","moon_phase"];
  foreach ($required as $k) {
    echo ($out[$k] !== null ? "PASS" : "FAIL") . " $k\n";
  }
  echo "Keys total: " . count($out) . "\n";
'

Edge-case fixtures to maintain:

  • EcoWitt cache missing or stale (tests graceful fallback)
  • Todo with only rest items, no urgents
  • Calendar with a recurring event and an EXDATE
  • No active Go games (empty board response)
Level 3 — Remote schema smoke test CLI After every deploy

After uploading and flushing, hit the live endpoint and verify the output shape. This confirms the server is running the new code and all caches are populated.

  go_ok:        (.go_opponent  != null),

  cal_ok:       (.cal_d0_dow   != null and .cal_d13_dow != null),
  moon_ok:      (.moon_phase   != null),
  forecast_ok:  (.f0_dow       != null and .f6_dow != null),

}'

Level 4 — Plugin HTML layout test HTML After plugin changes

Create a local test HTML file where all Liquid variables are replaced with hardcoded representative values. Open it in a browser resized to exactly 1040×780 (landscape) or 780×1040 (portrait) to verify layout before pasting into TRMNL.

Test file template:

<!-- plugin-go-todo-TEST.html -->
<!-- Replace every {{ variable }} with a literal value -->
<!-- Replace {% if condition %} with the branch that exercises the layout -->

<!DOCTYPE html>
<html><head><meta charset="utf-8"></head><body>

<!-- Paste plugin HTML here with Liquid replaced by literals -->
<!-- Example substitutions: -->
<!--   {{ go_opponent }}      → "GreenMonk"              -->
<!--   {{ go_color }}         → "b"                      -->
<!--   {{ go_moves }}         → "47"                     -->
<!--   {{ go_my_turn_count }} → "2"                      -->
<!--   {{ todo_total }}       → "11"                     -->
<!--   {{ todo_u0_text }}     → "A very long urgent item that might overflow its container" -->

</body></html>

Checklist for every plugin layout test:

  • No content clips at the right edge or bottom
  • Long text truncates with ellipsis, not overflow
  • Proportions hold at exactly 1040×780 landscape or 780×1040 portrait (use browser DevTools device mode)
  • Empty state: test with zero todo items, no active Go game, no calendar events
  • Go board renders with both a black stone and a white stone as the last move
  • Font sizes are legible at e-ink gray scale (avoid pure light grays like #ddd for text)
  • Today's calendar cell is clearly distinct from non-today cells
Tip

The TRMNL preview in the web dashboard re-renders on save. Use it for a final check after pasting — it shows the actual e-ink scaling and font rendering. But always do the local browser test first to catch layout issues before they hit the display.

Level 5 — Flush as integration test CLI After any PHP deploy

kaslo-flush.php doubles as an integration test: it invalidates OPcache and deletes all /tmp/kaslo_*.json caches. Fresh data is then fetched from all sources on the next plugin poll. Its output is the acceptance signal that the new PHP code is running.

curl -s https://knotwork.ca/kaslo-flush.php

Expected output:

OPcache invalidated: kaslo-api.php
OPcache reset: OK
Caches cleared

If OPcache reset fails, the old bytecode may still be running. Run the Level 3 smoke test immediately after to confirm the new code is active.

Section 06

Maintenance

EcoWitt API key (if ever rotated)

  1. Get new api_key from ecowitt.net.
  2. Update the ECOWITT_URL constant in kaslo-api.php.
  3. Run kaslo-flush.php to bust the stale weather cache.

BC Holidays

Defined in kaslo-api.php in the BC_HOLIDAYS array. The current entries cover 2026. Add 2027 dates before year-end — do it in November before the calendar window expands into 2027.

Test fixture freshness

Refresh the fixtures in test-fixtures/ every few months by copying the live /tmp/kaslo_*.json caches from the server. Stale fixtures won't catch regressions in how new data shapes are handled.

# Refresh fixtures from server
sftp kw_9g92aw@knotwork.ca <<'EOF'
get /tmp/kaslo_wx.json            test-fixtures/
get /tmp/kaslo_forecast3.json     test-fixtures/
get /tmp/kaslo_ical.json          test-fixtures/
get /home/kw_9g92aw/knotwork.ca/data/todos.json  test-fixtures/
EOF
